What is this system?

The AECID Traceability Monitor is an algorithmic audit tool that analyzes international cooperation funds managed by AECID, applying the Corrupt Phenomena methodology by Ph.D. Vicente Humberto Monteverde.

The system automatically detects breaks in the traceability chain of each fund — from the budget approved in Spain to the final beneficiary.

📊 The 7-Link Model

LinkStageDescription
L1Spain BudgetThe fund appears in the approved General State Budget.
L2AECID TransferThe receiving entity is identified (IO, NGDO or consultancy).
L3IO/BDNS RegistrationThe fund is registered in BDNS or in international organizations.
L4Geographic destinationThe destination country or region is publicly declared.
L5PLACE/OCDS ContractsDerived contracts are published on the procurement portal.
L6Public justificationFinal evaluations exist or positive responses to LTAIBG requests.
L7Final beneficiaryThe final beneficiary is identified with a tax ID or name.

🚨 The Three Main Ruptures

R1 IOs — Black box

Funds transferred to International Organizations (UNDP, UNICEF, FAO, UNHCR…) without breaking down the Spanish contribution in the IATI standard.

R2 Sub-contracting without OCDS

Contracts without publication on the State Procurement Portal (PLACE) under the Open Contracting Data Standard.

⚠️ Methodological note: if R2 appears at 100% for a fund today, it reflects that the automatic cross-check between AECID and PLACE has not yet been completed for that entity — it does not necessarily mean the contract is absent. The cross-check is built through a progressive backfill (page by page, with a persistent cursor) that advances with every pipeline run. While the backfill is in progress, a high R2 may overestimate the real risk. This indicator should be read together with the date of the last run, and it will gradually decrease as the backfill covers more contracts published on PLACE.

R3 No auditable justification

Projects with an amount over €500,000 without a published final evaluation nor a favorable response to an LTAIBG request (Law 19/2013).

🕸️ Graphs Tab (Dashboard)

The Dashboard includes a 🕸️ Graphs tab that visualizes the fund flow network as an interactive graph: AECID → Receiving entity → Link where traceability is cut.

  • The size of each entity node reflects the total amount channeled to that entity.
  • The node color reflects its risk classification: RED ORANGE YELLOW GREEN.
  • Dashed edges indicate funds without a traceable PLACE/OCDS contract (R2 rupture).
  • The square nodes E1–E7 represent the link where the traceability chain is cut for that entity.

Graph data is served from GET /api/grafo?top=N (see endpoints section), computed on-the-fly from analisis_completo.csv — no separate graph database is required.

🔌 API Endpoints

GET /api/status — Service status
GET /api/resumen — Executive KPIs
GET /api/fondos?entidad=X&clasificacion=ROJO&limit=100
GET /api/trazabilidad — Analysis by link
GET /api/entidades?top=30&nivel=Alto
GET /api/riesgo — Scores by entity
GET /api/grafo?top=30 — AECID → entity → cut-off link flow network
GET /api/mensual — Monthly evolution by region
GET /api/informe — Executive report in Markdown
POST /api/refresh (Header: X-Refresh-Token) — max. 1 call every 60s

🔐 Security and data refresh

POST /api/refresh triggers a run of the analysis pipeline. It requires a valid token in the X-Refresh-Token header — without it, or with an incorrect one, it returns 401. To prevent abuse, it is also rate-limited to one call every 60 seconds: a call within that window returns 429 until the remaining time has passed.

The rest of the API (GET /api/*) is read-only and requires no authentication — it serves already-processed public data.

📚 Theoretical framework

Based on the Corrupt Phenomena theory by Ph.D. Vicente Humberto Monteverde: regressive income transfers facilitated by discretion in legal decisions.
